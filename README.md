# B2B 아웃바운드 리드 발굴 실습

아웃바운드 CRM 제품을 만들기 전, **직접 dogfood 실습**으로 페인을 체득하고 가치 가설을 검증.

---

## 만들고 있는 제품

세일즈 인력 없는 초기 B2B 팀이 잠재 고객을 찾고, 한 곳 한 곳과의 관계를 관리해 첫 유료 고객을 만드는 **아웃바운드 CRM**.

핵심 기능: **리드 찾아주기 + 관계 관리.**

---

## 가장 중요한 정의

| 용어 | 의미 |
|---|---|
| **페르소나** | 우리 CRM 의 **고객 후보** ([personas.md](personas.md) 30개) |
| **리드** | 페르소나의 **영업 대상** = 페르소나의 "고객사" |

A11 페르소나 = CS 자동화 SaaS 만드는 초기 대표 (= 우리 고객 후보)
A11 의 리드 = CS팀 20명+ B2C 기업 (= 쿠팡·무신사 같은)

자세한 내용 → [CONTEXT.md](CONTEXT.md)

---

## 실습 방식

30개 페르소나 동시 진행 불가. **페르소나 1~2개 선택 → 그 페르소나 입장으로 리드 30개 발굴.**

진행:
1. 페르소나 선택 ([personas.md](personas.md) 에서)
2. `leads/{persona_code}/fields.md` 작성 (그 페르소나에 필요한 데이터 필드)
3. 발굴 사이클 시작 ([METHOD.md](METHOD.md))

---

## 폴더 구조

```
/lead
  CONTEXT.md          프로젝트 컨텍스트, 용어 정의
  personas.md         우리 CRM 의 고객 카탈로그 30개
  METHOD.md           리드 발굴 방법론
  viewer.html         CSV 동시 열람 뷰어
  leads/
    {persona_code}/
      fields.md            페르소나별 표준 데이터 필드
      leads.csv            리드(회사)당 1행
      data_points.csv      (리드 × 필드 × 소스)당 1행
      contacts.csv         (리드 × 사람)당 1행
      source_log.md        소스/키워드별 탐색 기록
      agent_log.md         세션 행동 기록
```

## 검증 포인트

| 관찰 | 시사점 |
|---|---|
| 리드가 어느 소스에서 나오는가 | 우리 제품의 데이터 소스 후보 |
| 어디서 막히는가 | 우리 제품이 풀어야 할 진짜 문제 |
| 한 리드당 소요 시간 | 페르소나가 느낄 페인의 정량값 |
| 의사결정자 도달 경로 | 우리 제품의 핵심 기능 흐름 |
